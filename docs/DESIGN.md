# Pedalfun 设计文档

整理日期：2026-11-19。本文是原生版（`native/`）的设计规范：页面、视觉、交互、动效、数据算法和代码结构都以这里为准。

**改动先改这里，再改代码。** 每次需求变化记进第 10 节，每个踩过的问题记进第 9 节，并且把结论写回对应的章节，而不是只留在记录里。

网页版（`src/`、`ios/`、`plugins/`）自 2026-11-19 起暂停开发，本文不再描述它。

## 1. 产品定位

一个纯粹的骑行码表工具。

- **只用手机 GPS 和手机自带传感器**（气压计、加速度计），不连接心率带、功率计、踏频计等外设。
- **不做**地图、路线规划、导航、社交、排行榜、训练课程。
- **好用优先于好看**：骑行中一瞥能读到数字，戴手套、颠簸时不会误操作。
- **平面风格**：纯色块，不用渐变、阴影、描边卡片。

功能范围的调研依据见 `docs/CYCLING-FEATURES.md`。

## 2. 页面

| 页面 | 作用 | 主操作 |
|------|------|--------|
| 首页 | 本周里程、七天柱状图、选中那天的数据、上次骑行 | 开始（圆形） |
| 骑行 | 实时数据 | 暂停（圆形）；暂停后：继续（圆形）、结束（圆形，长按） |
| 总结 | 刚结束的一次骑行 | 完成（胶囊形） |
| 骑行详情 | 从记录或首页点进来的历史骑行，版式同总结 | 导出 GPX（圆形） |
| 骑行记录 | 按月分组的列表，左滑删除 | 无 |
| 设置 | 偏好和个人资料 | 无 |

流转：

```
首页 ──开始──▶ 骑行 ──暂停──▶ 骑行（已暂停）──长按结束──▶ 总结 ──完成──▶ 首页
 │                ◀──继续──┘
 ├──▶ 骑行记录 ──▶ 骑行详情
 └──▶ 设置
```

所有页面共同的规则：

- **数据的位置固定**。状态变化只改颜色、强调和文字，不让数字换位置。
- **没有数据时显示 `--`**，格子照样留着。
- **单位写在小标签里**（「均速 km/h」），不跟在数字后面。例外是一屏里唯一的大数字（本周里程、本次里程、当前速度），单位放在数字右下。

### 2.1 首页

从上到下：本周里程（大数字）和一句本周摘要、七天柱状图、选中那天的数据、上次骑行卡片。

柱状图：

- 七根胶囊条是本周一到周日每天的里程，条下是星期和日期。
- **里程数字连同单位写在胶囊条正中间**，没骑的那天不写。
- 色块够高、盖过正中间时，数字压在色块上；色块矮时，数字留在色块上方的空槽里。数字不骑在色块的边缘上。
- **默认选中今天；点另一天的条切换。** 选中的条是绿色，其余是灰色。今天的星期和日期始终是绿字。还没到的日子变淡，不能选。

选中那天的数据：

- 一行小标题：「今天」或「周几」，加当天骑了几次。
- 一行四项，是当天所有骑行的合计：里程、均速、时间（移动时间）、消耗。
- 没填体重时消耗显示 `--`，小标题右边出现「填写体重以显示消耗」，点了去设置。

### 2.2 骑行页的数据

| 层级 | 内容 | 字号 |
|------|------|------|
| 速度区 | 当前速度，单位在右下角 | hero |
| 主要 | 时间、里程 | primary |
| 次要 | 均速、最高、爬升、海拔，四项一行 | secondary |
| 地形 | 坡度，加本次骑行的海拔剖面 | emphasis |

三层数据共用一套四列网格：时间和里程各占两列，四个小项各占一列，坡度占一列、剖面占三列。所有左边线对齐。层与层之间一条细线。

### 2.3 骑行页的状态

| 状态 | 速度区 | 其他 |
|------|--------|------|
| 骑行中 | 绿底白字，「记录中」 | 暂停按钮 |
| 上坡（坡度 ≥ 3%） | 不变 | 坡度变红色胶囊，标签「上坡」 |
| 下坡（坡度 ≤ −3%） | 不变 | 坡度变绿色胶囊，标签「下坡」 |
| 自动暂停 | 灰底白字，「自动暂停，起步后继续」 | 时间标签加「已停表」；坡度归零；仍是暂停按钮 |
| 手动暂停 | 深色底、数字变灰，「已暂停」 | 时间标签加「已停表」；坡度归零；继续 + 结束 |
| GPS 弱 | 速度显示 `--` 并变淡，状态文字变黄 | 信号条只亮一格 |
| 刷新最高速度 | 不变 | 「最高」的数字变绿一下（骑行 45 秒后才触发） |

规则：

- **坡度只在计时进行时显示**。停表后一律显示 0.0、不着色。
- **GPS 弱只在骑行中提示**。暂停时显示暂停状态，不显示 GPS 警告。
- **信号不可信时不显示数字**，显示 `--`，不显示一个可能错误的速度。

### 2.4 总结页和骑行详情

**一屏显示完，不滚动。** 从上到下：

- 骑行名称（刚结束时加「已保存」）、本次里程（大数字）。
- 海拔剖面，高度随屏幕伸缩。下面一行：起点 0、图例（平路、下坡、上坡）、终点里程。
- 四类数据，每类一行，左边一列写类别名，类与类之间一条细线：

| 类别 | 内容 |
|------|------|
| 时间 | 移动时间、总耗时 |
| 速度 | 均速、最高 |
| 海拔 | 爬升、最高 |
| 消耗 | 估算的千卡数 |

屏幕矮时先压缩剖面和行间的空白，数字字号不变。

### 2.5 骑行记录

- 按月分组，月份标题带当月次数和里程。
- 每行：日期和名称、里程、移动时间、爬升、一小段海拔剖面。点进去是骑行详情。
- 左滑露出红色删除按钮，点了这一行收起。不另加确认弹窗。

### 2.6 设置

| 分组 | 项 | 控件 |
|------|----|------|
| 偏好 | 单位（公里 / 英里） | 分段选择 |
| | 外观（深色 / 浅色 / 自动） | 分段选择 |
| | 自动暂停、骑行时屏幕常亮、震动反馈 | 开关 |
| 个人资料 | 性别（男 / 女） | 分段选择，可以不选 |
| | 身高 cm、体重 kg | 数字输入 |

- 个人资料只用来估算消耗（第 6.6 节），三项都可以不填。身高、体重固定用公制。
- 数字输入超出合理范围（身高 100–230，体重 30–200）按没填处理。
- 滚动页面或点键盘上的「完成」收起键盘。

## 3. 视觉规范

### 3.1 颜色

深色为默认，浅色用于强光。两套都只有三类颜色：底色与文字、绿、红；另有一个只在 GPS 警告时出现的黄色。

| 用途 | 深色 | 浅色 |
|------|------|------|
| 底色 | `#363744` | `#F3F4F6` |
| 次级底色（卡片、开关底、分隔线） | `#434451` | `#E4E6EA` |
| 文字 | `#FFFFFF` | `#2B2C36` |
| 次级文字 | `#A9AAB4` | `#6B6D78` |
| 更弱的文字 | `#7F808B` | `#A0A2AC` |
| 绿（开始、暂停、继续、完成、下坡、今天、选中的那天） | `#2BD78E` | `#1FC47E` |
| 红（结束、删除、上坡） | `#F25050` | `#EE4B4B` |
| 速度区：骑行中 | `#1FC480` | `#1FC480` |
| 速度区：自动暂停 | `#5C5D6B` | `#9A9DA8` |
| 速度区：手动暂停 | `#26272F` | `#2B2C36` |
| 黄（仅 GPS 警告） | `#FFC94A` | `#C98A00` |

规则：

- **绿表示「走」，红表示「停」和「上坡」**。不引入第四种强调色。
- **速度区的文字用白色**，不用黑色。速度区的绿比按钮的绿深一档，保证白字可读。
- **坡度不按陡峭程度分级着色**，只分上坡、下坡、平路；陡不陡看数字。
- **海拔剖面图用同一套颜色**：平路灰、上坡红、下坡绿。
- **压在色块上的字要和色块对比**：绿色块上用白字，灰色块上用底色字，空槽里用正文字色。

### 3.2 字体

- **数字**：Barlow Condensed（Bold 和 SemiBold），随 App 打包。窄体，所以数字能做大。
- **数字必须等宽**（tabular）。数值变化时相邻内容不能左右抖动。
- **文字**：系统字体。
- **数字不加滚动或翻转动画**，直接跳变，一瞥最易读。

字号按角色取值，页面不自定字号。

数字（`TypeScale`）：

| 角色 | 字号 | 用在哪 |
|------|------|--------|
| hero | 156 | 骑行页速度 |
| display | 92 | 首页本周里程、总结页里程 |
| primary | 50 | 骑行页时间、里程 |
| stat | 36 | 总结页各项数据 |
| emphasis | 32 | 坡度、记录列表的里程 |
| secondary | 26 | 骑行页均速、最高、爬升、海拔 |
| card | 24 | 首页选中那天的数据、上次骑行卡片、顶部字标 |
| unit | 22 | 速度单位、设置里的数字输入 |
| inline | 19 | 夹在小字里的数字 |
| date | 15 | 柱状图下的日期 |
| label | 13 | 柱状图里的里程 |

文字（`TextScale`）：

| 角色 | 字号 | 用在哪 |
|------|------|--------|
| title | 16 | 顶栏标题、设置项名称、大数字旁的单位 |
| body | 15 | 骑行名称、月份标题、类别名、空状态说明 |
| note | 14 | 本周摘要、骑行状态、提示条、分段选择的选项 |
| label | 13 | 数据标签、单位、设置项说明 |
| caption | 12 | 星期、图例、剖面刻度 |
| micro | 10 | 柱状图里的单位 |

### 3.3 尺寸

所有页面共用，改一处全局生效（`Metrics`）。

| 项 | 值 | 说明 |
|----|----|------|
| 左右边距 | 24 | |
| 顶栏高度 | 52 | 骑行页以速度区代替顶栏 |
| 底部按钮区高度 | 148 | 在 Home 指示条之上；按钮在其中垂直居中 |
| 圆形按钮直径 | 80 | 开始、暂停、继续、结束、导出；图标是直径的 0.36 |
| 完成胶囊 | 184 × 64 | |
| 两个并排按钮的间距 | 84 | 继续与结束 |
| 数据网格的列间距 | 12 | 骑行页、首页当日数据、总结页 |
| 细线 | 1 | 层与层、类与类之间 |
| 坡度胶囊的留白 | 左右 16，上下 8 | |
| 柱状图 | 条间距 14，最高 150 | 条内文字占正中上下各 15 |
| 总结页类别列宽 | 52 | |
| 总结页剖面高度 | 40–96 | 随屏幕伸缩 |
| 设置行最小高度 | 68 | |
| 数字输入 | 高 42，数字区宽 58 | |
| 卡片圆角 | 22 | 上次骑行卡片 |

规则：

- **每个页面的主按钮在同一高度**，圆心距屏幕底边约 108 点，落在拇指自然够得到的位置。
- **按钮不要做得过大**。
- **坡度胶囊贴着文字包裹**，左右留白相等。文字位置不因胶囊出现而移动。

### 3.4 图标与文字

- **能用图标的不用文字**：开始和继续是播放，暂停是暂停，结束是方块，完成是对勾，删除是垃圾桶，导出是分享。
- **数据标签保留文字**。均速和最高速度这类字段用图标无法一眼区分，骑行中看错的代价高。
- **顶部状态保留文字**（记录中、已暂停、自动暂停）。
- **完成用胶囊形**，其余主操作用圆形，这样总结页和首页一眼能分开。

## 4. 交互规范

| 操作 | 方式 | 理由 |
|------|------|------|
| 开始 | 轻点 | 立即开始 |
| 暂停 | 轻点 | 立即暂停，等红灯时常用 |
| 继续 | 轻点 | |
| 结束 | 长按 0.6 秒 | 不可撤销，防颠簸误触 |
| 完成 | 轻点 | |
| 删除记录 | 左滑后点删除 | 两步，不另加确认弹窗 |

长按规则：

- **手指触屏的瞬间就开始计时**，同一时刻震动、按钮缩小、外圈红环开始走。延迟应在毫秒级。
- **红环匀速走满一圈的时刻就是触发的时刻**，中间没有「环满了还在等」。
- **提前松手**：红环退回，并提示「长按结束骑行」。长按按钮上不写「长按」二字，靠这句提示教会用户。

保存规则：

- **骑行结束即自动保存**，没有保存和丢弃的选择。不想要的记录到列表里左滑删除。
- **很短的骑行也会保存**（未定是否要自动忽略，见第 11 节）。

其他：

- **第一次点开始时请求定位权限**，在离开首页之前。被拒绝则留在首页并说明去哪里打开。
- **骑行中屏幕常亮**（可在设置里关）。
- **震动**：开始、暂停、继续各一下；长按起始轻、完成重；自动暂停轻、自动继续中。

## 5. 动效规范

所有动画参数集中定义（`Motion`），页面按角色引用。

| 角色 | 表现 | 时长 |
|------|------|------|
| 按下 | 缩到 0.94，带回弹 | 弹簧 0.3 |
| 页面切换 | 进入时自右推入并淡入，返回时自左 | 0.26 秒 |
| 开始 · 铺满 | 绿色从开始按钮向外铺满全屏 | 0.43 秒 |
| 开始 · 收拢 | 绿色向上收拢成速度区 | 0.40 秒 |
| 数据入场 | 三层数据依次上浮淡入 | 0.42 秒，层间隔 0.06 秒 |
| 暂停按钮入场 | 先不可见，延迟 0.3 秒后由小到大淡入、略回弹 | 弹簧 0.45 |
| 暂停 ⇄ 继续 + 结束 | 一个按钮分裂成两个，反向合并 | 弹簧 0.36，各移 82 |
| 速度区、坡度胶囊变色；柱状图换选中的那天 | 渐变 | 0.35 秒 |
| 坡度胶囊出现 | 弹一下 | 弹簧 0.42 |
| 刷新最高速度 | 变绿后淡回 | 停 0.6 秒，淡出 1 秒 |
| 设置里的选择 | 选中块滑过去 | 弹簧 0.3 |
| 周柱状图 | 逐根长出，长完后条内数字淡入 | 0.5 秒，间隔 0.045 秒；数字 0.25 秒 |
| 海拔剖面 | 自左向右展开 | 0.7 秒 |
| 删除记录 | 这一行淡出并收起，下面的行上移 | 0.25 秒 |
| 提示条 | 淡入淡出 | 0.18 秒 |

规则：

- **一个元素的入场动画只属于它自己**，不挂在父容器上。挂在父容器上的动画会被别的状态切换打断。
- **入场的起始状态在元素显示之前就设好**，不能先以完整大小画一帧再开始动。
- **按下的回弹动画只作用于按钮盘面**，不能波及进度环或其他有独立节奏的部分。
- **变色时文字和底色同步渐变**，避免瞬间出现深色字压深色底。
- **一个变化只由一方来动**。列表删除由我们自己收起这一行，就不再让系统播它的删除动画，否则两段动画会打架。
- **系统开启「减弱动态效果」时**跳过开始过渡，直接进入骑行页。

## 6. 骑行数据

### 6.1 定义

| 字段 | 定义 |
|------|------|
| 速度 | 定位芯片给出的瞬时速度（多普勒），经过第 6.2 节的校验 |
| 时间 | 移动时间，自动暂停和手动暂停期间不计 |
| 总耗时 | 从开始到结束的墙上时间，只在总结页显示 |
| 里程 | 相邻有效定位点的球面距离之和 |
| 均速 | 里程 ÷ 移动时间 |
| 最高 | 本次的最大瞬时速度（校验后的），GPS 弱时的读数不计入 |
| 海拔 | 有气压计时：起点 GPS 海拔 + 气压计相对高度；否则：平滑后的 GPS 海拔 |
| 爬升 | 累计上升，带回差，平路上的传感器噪声不累加 |
| 坡度 | 按一段距离窗口计算，不用相邻两点 |
| 消耗 | 按均速、移动时间和个人资料估算（第 6.6 节） |

### 6.2 速度校验

系统给的速度经过它自己的滤波，信号差时会滞后：车已经停了或者下车推行，读数还停在骑行时的速度上慢慢往下掉。所以显示、判停和最高速度用的都是校验后的速度：

| 情况 | 处理 |
|------|------|
| 系统标明速度无效，或速度误差大于 2.5 m/s | 不用它，改用最近 2 秒的位移除以时间 |
| 系统速度明显高于最近 2 秒的位移速度（超过 1.5 倍再加 1 m/s） | 判定为滞后，用位移速度 |
| 一秒内速度上升超过 3 m/s（自行车做不到） | 判定为跳变，上升幅度限制在 3 m/s²；下降不限制 |

- **位移速度只用来把偏高的读数拉下来，不用来把读数抬上去**：位置噪声只会让位移速度偏大，用它抬高读数，会在原地站着时显示出速度。
- 校验在每个定位点上都做，手动暂停期间也做，这样继续时速度是现成的。

### 6.3 自动暂停

- **判停**有两条路：
  - 速度低于 0.6 m/s，持续 2.5 秒确认。
  - 加速度计显示手机静止，且速度低于 1.4 m/s（此时的速度是 GPS 漂移）：收到第一个这样的定位点就确认，速度直接显示 0。定位每秒一个，所以大约 1 秒。
- **判走**有两条路：
  - 速度高于 1.2 m/s 且不是静止状态下的漂移，持续 1 秒确认。
  - 加速度计显示手机在晃动，且速度高于 2 m/s：不等确认，立刻继续。
- **回溯**：确认停车后，时间和里程回滚到刚开始停的那一刻；确认起步后，把确认期间缓冲的点补算回去。确认用掉的那几秒不进入记录。
- **手动暂停时正在确认的停车**直接按已停车处理并回溯。
- 设置里可以关闭；关闭后停车时间计入移动时间。

### 6.4 数据质量

| 情况 | 处理 |
|------|------|
| 水平精度差于 35 米 | 标记 GPS 弱，速度显示 `--` |
| 水平精度差于 65 米 | 该点不计里程，也不参与位移速度 |
| 两点间速度超过 35 m/s | 视为位置跳变，丢弃 |
| 两点间隔超过 15 秒且几乎没移动 | 该间隔不计移动时间 |

### 6.5 阈值

全部集中在 `RideTracker.Tune`，别处不写数字。**这些是估计值，只经过一次真机骑行的反馈，没有系统路测**，尤其要留意慢速爬陡坡不能被误判成停车。

| 名称 | 值 | 含义 |
|------|----|------|
| weakAcc | 35 m | 精度差于此标记 GPS 弱 |
| rejectAcc | 65 m | 精度差于此不计里程 |
| maxSpeed | 35 m/s | 两点间快于此是位置跳变 |
| stopSpeed | 0.6 m/s | 低于此算停 |
| driftSpeed | 1.4 m/s | 手机静止时，低于此算漂移 |
| goSpeed | 1.2 m/s | 高于此算走 |
| fastGoSpeed | 2.0 m/s | 手机晃动时，高于此立刻继续 |
| stillMotion | 0.012 g | 加速度计低于此算静止；高于它的两倍算晃动 |
| stopConfirm | 2.5 s | 判停的确认时间 |
| stillConfirm | 1.0 s | 加速度计佐证时的判停确认时间 |
| goConfirm | 1.0 s | 判走的确认时间 |
| speedAccLimit | 2.5 m/s | 系统速度误差大于此不用 |
| posWindow | 2.0 s | 位移速度的时间跨度 |
| lagRatio、lagMargin | 1.5、1.0 m/s | 系统速度高于「位移速度 × 比例 + 余量」算滞后 |
| maxAccel | 3.0 m/s² | 速度上升的上限 |
| maxGap | 15 s | 两点间隔超过此且几乎没动，不计时间 |
| baroClimb、baroWindow | 1.5 m、40 m | 气压计：爬升回差、坡度窗口 |
| gpsClimb、gpsWindow | 4 m、100 m | GPS 海拔：爬升回差、坡度窗口 |
| sampleEvery | 20 m | 海拔剖面的采样间距 |

### 6.6 消耗估算

只用均速、移动时间和个人资料估算，没有心率和功率，所以只是一个粗略的数。

- **基础公式**：消耗（千卡）= 代谢当量 × 体重（公斤）× 移动时间（小时）。
- **代谢当量**按均速取值，数值来自《体力活动汇编》的骑行条目，相邻两档之间线性过渡：

| 均速 km/h | ≤ 8.9 | 15.1 | 17.6 | 20.8 | 24.1 | 28.2 | ≥ 33 |
|-----------|-------|------|------|------|------|------|------|
| 代谢当量 | 3.5 | 5.8 | 6.8 | 8.0 | 10.0 | 12.0 | 15.8 |

- **个人修正**：性别和身高都填了时，按 Mifflin-St Jeor 公式算出静息代谢，再乘以 `25.2 × 体重 ÷ 静息代谢`。公式需要年龄，没有登记年龄，统一按 30 岁算。
- **必须有体重**才显示；性别、身高没填时不做个人修正。
- 消耗不存进骑行记录，显示时按当前的个人资料现算。改了体重，历史骑行的消耗会跟着变。
- 没有考虑爬升、风和路面。

## 7. 存储与导出

- 设置存在系统偏好里。
- 每次骑行一个摘要文件和一个轨迹文件，放在应用支持目录的 `rides/` 下。启动时只读摘要，导出时才读轨迹。
- 轨迹在每次暂停处分段。
- 导出为 GPX 1.1，通过系统分享面板送出。没有轨迹的记录不能导出，并给出提示。

## 8. 架构

原生版，SwiftUI，iOS 17 起。工程由 `native/project.yml` 经 `xcodegen` 生成，新增文件后要重新生成。

```
App/     入口、路由与开始过渡（AppModel）、根视图
Core/    不依赖界面
  采集     LocationRecorder     定位、气压计、加速度计
  计算     SpeedEstimator       定位点 → 可信的速度（纯逻辑）
           RideTracker          定位点 → 骑行数字（纯逻辑，阈值在 Tune）
           Calories             均速、时间、个人资料 → 消耗（纯逻辑）
           WeekStats            骑行记录 → 本周每天的合计（纯逻辑）
  会话     RideSession          一次骑行：recorder → tracker → 状态
  显示规则 RidePresentation     骑行状态 → 骑行页显示什么
           HomePresentation     本周统计 → 首页显示什么
           SummaryPresentation  一次骑行 → 总结页显示什么
  其他     RideStore / Settings / GPX / Format / Haptics / Demo
UI/
  Design.swift     配色、数字字号、文字字号、尺寸、动效的全部常量
  Components/      Buttons 按钮 · Controls 分段选择、开关、数字输入 ·
                   Readouts 数字、标签、数据格、细线、GPS 信号 ·
                   WeekBars 周柱状图 · ElevationProfile 海拔剖面 ·
                   Chrome 顶栏、页面骨架、按钮区、提示条
  Screens/         五个页面，只负责摆放
```

规则：

- **颜色、字号、共用尺寸、动效都取自 `Design.swift`**，页面和组件里不自己定。页面里还留着的数字只有相邻元素之间的间距。
- **每个页面都建在 `ScreenScaffold` 里**（顶部、内容、底部按钮区），由它保证各页高度一致。
- **「显示什么」和「怎么摆」分开**。文字、单位、选中与否、用哪种颜色状态由 `…Presentation` 决定，它们是纯数据，可以直接测；页面只布局。
- **一份数据格只有一种画法**。「小标签 + 数字」统一用 `Stat`，分隔统一用 `Hairline`。
- **计算不碰界面、不碰存储、不用定时器**，只由输入驱动，所以能直接单元测试。
- **阈值只在 `RideTracker.Tune`**，速度校验也从那里取。
- **需要零延迟的触摸直接读系统触摸事件**，不走手势识别。
- **看界面用的启动参数只对这一次启动生效**，不写进用户设置。

## 9. 从问题中得到的规则

每个问题都对应上文的一条规则，能自动检查的配了测试。

| 问题 | 原因 | 规则 | 检查 |
|------|------|------|------|
| 长按结束迟迟没反应 | 手势识别要先分辨手势类型才通知按下 | 零延迟的触摸直接读系统事件（第 4、8 节） | 界面测试：触摸到响应的延迟低于 50 毫秒，实测 1–3 毫秒 |
| 长按时红环很快走满，然后空等 | 按下的回弹动画波及了红环 | 回弹只作用于盘面（第 5 节） | 人工 |
| 点开始后暂停按钮闪一下 | 入场动画挂在父容器上被打断，随后又被重复触发 | 入场动画只属于元素自己，起始状态先设好（第 5 节） | 人工 |
| 坡度变色时一瞬间看不清字 | 文字颜色瞬间切换，底色在渐变 | 文字和底色同步渐变（第 5 节） | 人工 |
| 坡度胶囊出现时文字位置变了 | 胶囊占满整格，文字随对齐方式移动 | 胶囊贴着文字包裹，文字不动（第 3.3 节） | 人工 |
| 数字变化时相邻内容抖动 | 数字不等宽 | 数字必须等宽（第 3.2 节） | 人工 |
| 数据区看起来乱 | 上一行两列、下一行三列，边线错位 | 三层共用四列网格（第 2.2 节） | 人工 |
| 点删除时先收回这一行，结果打开了详情 | 按下删除被当成点在别处 | 原生版改用系统的左滑删除 | 界面测试：左滑删除后少一行 |
| 停车后几秒才暂停，这几秒被算进时间 | 确认延迟直接进了数据 | 自动暂停回溯（第 6.3 节） | 单元测试：停 20 秒的骑行移动时间正好 90 秒 |
| 看界面用的主题参数改掉了用户设置 | 参数被写进了设置 | 启动参数只对这一次启动生效 | 人工 |
| 左滑删除时红色按钮位置跳一下 | 给按钮标了「销毁」角色，系统会自己播一段删除动画，和我们的数据更新打架 | 删除按钮不标销毁角色，这一行用统一的动效收起（第 5 节） | 录屏逐帧看过；界面测试：左滑删除后少一行 |
| 推车步行显示 20 多 km/h；停车后速度慢慢往下掉 | 系统速度未经校验直接显示，信号差时它会滞后或跳变 | 速度校验（第 6.2 节） | 单元测试：系统速度滞后、跳变、无效三种情况 |
| 停车和起步反应慢 | 只靠速度阈值加固定确认时间 | 加速度计能佐证时缩短确认（第 6.3 节） | 单元测试：位移停下后的第一个静止定位点就暂停，起步 2 秒内继续 |
| 看界面用的个人资料参数被存了下来 | 可选值在初始化时赋值也算一次修改，触发了保存 | 读完设置之后才开始保存（第 8 节） | 人工：带参数启动后检查偏好文件 |

## 11. 未解决和待验证

**没有在真机上验证过的：**

- 第 6.2 节的速度校验和第 6.3 节缩短后的确认时间，改完后还没有路测。
- 锁屏和后台时是否持续记录。
- 气压计得出的爬升和坡度是否合理。
- 手机放在口袋或背包里时，停车后身体仍在动，加速度计帮不上忙，判停走 2.5 秒的慢路径。
- 很平的路面上滑行时，加速度计会不会低到被当成静止。
- 强光下的可读性。
- 比 iPhone 15 Pro 更矮的屏幕上，总结页能否一屏放下。

**没有做的：**

- 记录原始定位数据。现在显示不对时无法回放，只能靠推断调阈值。
- 起步时系统速度偏低的滞后没有修，只是去掉了确认等待。
- 骑行中途存档。骑行时 App 被系统终止，当前这次记录会丢失。
- 很短的骑行（例如开始后马上结束）也会保存，没有自动忽略。
- 删除没有撤销。
- 没打开 App 时自动开始记录。

**需要决定的：**

- 消耗估算要不要登记年龄（现在统一按 30 岁）。
- 消耗估算要不要换成按体重、速度和爬升估功率的算法。现在的算法不考虑爬升，数字可能偏高。
- 骑行页的海拔剖面在噪声下会呈红绿灰相间的条纹，要不要改成按更长的距离判断颜色。
- 网页版的代码是否从仓库里移走。
